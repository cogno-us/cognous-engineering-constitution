# Cognous Engineering Constitution

Cross-project engineering principles and static orchestration practice.

- [ENGINEERING_CONSTITUTION.md](ENGINEERING_CONSTITUTION.md): EP01–EP18, documentation invariant DOC-01, review tiers and evidence discipline.
- [ORCHESTRATION.md](ORCHESTRATION.md): worker ownership, task contracts, scheduling, independent qualification, integration and reporting.

These documents govern how authorized engineering work is performed. Reading them does not authorize a project, architectural change, expenditure, external effect, deployment or release. Platform and organizational controls remain higher priority. Project architecture, exact contracts, source pins, environment permissions and explicitly reserved decisions remain in each project's own governed records.

Project repositories should reference the adopted revision of these shared documents and retain only their project-specific overlay. An overlay supplies project sources, interfaces, ownership, qualification profiles and applicable boundaries; it does not create a competing copy of the common principles. Changes use reviewable revisions and the risk-tier policy in the constitution. Routine documentation changes receive self-validation and required automated checks, without ceremonial independent review.

Canonical programs remain stateless. Current assignments, authorizations, pull requests, checks, blockers and results belong in designated project telemetry; immutable historical evidence remains in its original custody. This repository is not a cross-project status dashboard.

## Extraction provenance

The common material was extracted from `cogno-us/cognous-iss-v6`, `docs/engineering/ENGINEERING_CONSTITUTION.md` and `docs/engineering/ORCHESTRATOR_MASTER_PROMPT.md`. The extraction retains the adopted engineering articles and general workflow while replacing project role names with functional roles. The adopted constitution controls over superseded article-status language in the older orchestration prompt.

Project architectural summaries, proprietary-source identities and locators, implementation crosswalks, project identifiers, historical authorization selections, active holds and current execution state are intentionally retained in project-local records rather than published here. This extraction does not change their authority or rewrite historical evidence. It introduces no new engineering requirement.
