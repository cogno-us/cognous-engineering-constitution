# ChatGPT Skill: Cognous Engineering Governance

This directory contains the portable, derived ChatGPT skill for applying the constitution to engineering work. **It is not an adoption instrument and does not authorize execution, merges, release, deployment, spending, or certification.** The primary repository documents and each project's exact adopted revision control.

## Contents

- `SKILL.md`: entrypoint and task routing
- `agents/openai.yaml`: ChatGPT display metadata
- `references/constitutional-articles.md`: EP/CA reference and verbatim article table at recorded snapshot
- `references/orchestration-assignments.md`: role/archetype routing, eight-field packets, ownership and parallel work
- `references/testing-qualification.md`: risk-tiered tests, evidence, CI and independent qualification
- `references/adoption-authority.md`: authority, adoption, amendments, provenance
- `references/templates.md`: operational templates
- `references/source-manifest.md`: revision and primary document mapping

## Usage and installation

Upload a ZIP archive containing this **entire** `cognous-engineering-governance/` directory to ChatGPT Skills management. Keep the structure intact with `SKILL.md` at the directory root. Invoke it for source-grounded builder assignments, engineering compliance, PR reviews, test scoping, qualification and adoption questions. Verify the actual project's constitutional adoption and exact source pins before applying normative controls or producing executable assignments.

## Maintenance and source fidelity

The skill was first derived from the repository snapshot inspected on 2026-11-04; the precise observed source tree and source-document status are recorded in `references/source-manifest.md`. The bundled references are **derived guidance**, not complete historical snapshots of every primary document. To revise, inspect all root normative documents, applicable addenda and `schemas/orchestrator-assignment-v1.schema.json`; update the source manifest, the normative article slices, workflows, and tests as needed. Check text fidelity against the exact selected canonical revision; do not silently promote proposed addenda or change prior adoptions. Review modifications in a PR, preserve predecessor history, validate the package, and only then distribute a new archive.
